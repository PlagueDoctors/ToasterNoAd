# NoAd

> 一个 Android 广告拦截应用，自动跳过应用开屏广告与应用内弹窗广告。
>
> ⚠️ **项目开发中** —— 当前完成度较低，本 README 仅作初步介绍，全部功能完成后会补充完整文档。

---

## 这是什么

手机上大量应用在启动时展示开屏广告、在使用中弹出插屏广告。手动点击「跳过」既打断操作，
部分广告的关闭按钮还做得极小、延迟出现，甚至伪装成其他按钮。

NoAd 的目标是**自动完成这些点击**，让广告出现即消失。此外还规划了网络层的域名过滤能力，
用于拦截网页横幅与追踪域名。

本项目**仅个人自用与开源研究**，不以上架应用商店为目标。

## 四种策略的分工

它们**不是可替换的同类选项**，而是覆盖不同层面的问题：

```
S1 无障碍点击 ── UI 层：能"看见并点击"的广告（开屏、弹窗）
S2 DNS 过滤  ── 域名层：让广告服务器域名解析失败
S3 VPN 过滤  ── 网络层：按规则丢弃/重写请求（能力最强，代价独占 VPN）
S4 应用断网  ── UID 层：按包名切断整个应用联网（不占 VPN，需 Shizuku）
```

**关键约束**：Android 同一时刻只允许一个 VpnService 运行。
因此 S2 与 S3 **互斥**；S1 与它们可并存；S4 不占 VPN，可与任意组合叠加。

**诚实说明**：信息流原生广告（广告内容与正文同服务器同域名）**四种策略都拦不住**，
这是技术边界而非缺陷。

## 如何使用

### 安装

```bash
./gradlew assembleDebug
adb install app/build/outputs/apk/debug/app-debug.apk
```

### 开启 S1（两层授权，缺一不可）

1. **系统层**：打开 NoAd → 首页「无障碍拦截」卡片 → 「去开启」→
   在系统无障碍设置中找到「NoAd 广告拦截」并打开
2. **应用层**：在应用内打开「无障碍拦截」开关
3. **纳管应用**：进入「应用管理」页勾选需要拦截的应用

> ⚠️ **默认不纳管任何应用**，未勾选前不会拦截任何东西。
> 如果发现「没效果」，先检查这里。

> ⚠️ **Android 13+ 侧载限制**：从浏览器等渠道安装 APK 时，无障碍列表里可能
> **看不到** NoAd。需要到「应用信息 → 右上角菜单 → 允许受限设置」放行后重试。

### 关于「服务已暂时断开」（这是正常的，不用重新授权）

息屏、切换应用、内存紧张之后，你可能会看到首页卡片显示
**「已授权，服务暂时断开」**。这是 Android 的正常行为，**不是权限被撤销**：

- 无障碍是**授权模型**：你在设置里勾选后，由**系统**决定何时连接、何时解绑服务
- 系统解绑服务实例时，**设置里的开关仍然是开着的**
- 因此**不需要重新授权**，系统通常会自动重新连上

NoAd 会在息屏、解锁、授权变化、以及你切回应用时主动核对状态，
并在检测到断开时把它如实显示出来（附带断开时长与原因），而不是假装一切正常。

> 如果长时间未恢复，点卡片里的「前往设置检查」确认开关状态即可。
>
> **注意**：没有任何应用能让无障碍"永不掉线"——包括 NoAd。
> 那些宣称靠"保活"稳定无障碍的做法是无效的：前台服务、定时任务影响的
> 是进程优先级，而无障碍服务的绑定由系统独立管理。

### 后台保活（进程被杀后自动恢复）

上面一节说的是**无障碍服务掉线**（进程还活着，系统暂时解绑）。
另一种更彻底的情况是**整个进程被系统杀掉**——内存回收、厂商一键清理等。
这时无障碍服务也随之消失。NoAd 的保活机制针对的就是这一层：

- **三层自恢复链**：进程被杀后，靠「粘性重启 → 心跳闹钟 → 系统广播」
  三条独立通路互相备份，把进程重新拉起；无障碍服务随之由系统自动重连。
- **两个独立开关**（设置 → 通用）：
  - 「后台保活」：管运行期不被杀 + 被杀后自动恢复（默认开启）
  - 「开机自启动」：管设备重启后是否恢复保活（默认关闭）
- **电池优化豁免入口**：设置里可一键跳转系统授权页。豁免后进入官方
  后台启动豁免名单，在激进省电 ROM（一键清理类）上恢复成功率显著提升。
- 常驻通知为**低优先级静默渠道**，不响铃不横幅；Android 13+ 会请求
  通知权限，拒绝只影响通知可见性，服务照常运行。

**诚实边界**：

- 「设置 → 应用 → 强制停止」之后，**任何应用都无法自启**（Android 安全
  设计），保活链也不例外。需要重新打开一次应用。
- 保活提高的是**进程存活的概率**，不能让无障碍"永不掉线"——掉线与
  被杀是两种不同的失效，前者见上一节。

### 最近任务隐藏与常驻拦截动态

- **上划后台应用列表里看不到 NoAd**：这是刻意的（`excludeFromRecents`）。
  隐藏的只是任务卡片，点桌面图标照常回到原界面；附带收益是无法从
  最近任务里划掉或一键清理本应用（与保活互补）。
- **常驻通知实时显示拦截动态**：保活通知的标题为「已拦截 N 次广告」，
  正文为「最近拦截：某应用 · 广告类型」，每次新拦截即时更新。
  更新**只在下拉通知栏呈现，不弹横幅、不发声**（低优先级渠道的结构性保证）。
- 「设置 → 通用 → 拦截动态」控制常驻通知是否显示以上内容；
  关闭后回退为静态保活文案。通知本身不可移除（前台服务的系统要求），
  想彻底关掉请关闭「后台保活」。
- 通知计数与「拦截日志」页条数同源（同一张表）：日志按容量裁剪后，
  计数会随之回落到上限内，两个数字永远一致。

### 侧载被「受限设置」挡住？用 Shizuku 一键解除（Android 13+）

如果 NoAd 是侧载安装的（非应用商店），在 Android 13+ 上系统可能把
无障碍设置里 NoAd 的开关**隐藏或禁用**（"受限设置"限制）——
这是系统安全机制，不是 NoAd 出了问题。

NoAd 提供自动解除（需要安装 [Shizuku](https://shizuku.rikka.app/)）：

- **没装 Shizuku**：首页引导卡保持手动图文引导，一切功能不受影响
- **装了没授权**：卡片显示「授权 Shizuku」按钮，点一下授权即可
- **已授权**：卡片显示「用 Shizuku 自动解除」—— NoAd 通过 Shizuku
  给自己放行 `ACCESS_RESTRICTED_SETTINGS` 开关，**回读验证确认生效后**
  直接打开系统无障碍设置，此时开关已恢复可见可开
- **包级解除不生效**：自动降级 `--uid` 级再验证；仍失败则保持手动
  引导并给出失败提示

诚实边界：

- Shizuku **不是 root**，只是 shell（UID 2000）级别授权；
  NoAd 用它只做两件事：给自己的受限设置开关放行（解除限制）、
  以及在授权被系统清理后恢复无障碍授权记录（见下节）
- Shizuku 重启后（设备重启/被杀）需要重新启动它；在此之前 NoAd
  自动回退手动图文引导，除「解除/恢复」外的全部功能完全不受影响
- 解除结果**不跨进程记忆**：如果重启 NoAd 后系统仍有限制，
  提示卡会重新出现，再点一次解除即可
- 商店安装的用户不存在此限制，整个入口不会出现

### 授权被「一键清理」清掉了？一键恢复（Shizuku 或 adb 高级授权）

部分 ROM 的「一键清理 / 上划清除」按**强制停止**语义处理应用：
进程被杀的同时，系统把无障碍授权记录一并撤销 —— 表现为首页显示
「未开启」，必须去系统设置重新勾选。这是系统行为，任何应用都无法阻止，
NoAd 能做的是把「重新开启」变成一次点击，有两条通道（自动择优）：

- **adb 高级授权（推荐，无需 Shizuku）**：电脑上执行一次
  `adb shell pm grant com.toaster.noad android.permission.WRITE_SECURE_SETTINGS`
  即终身有效（重启不失效，卸载重装需重新授权）。操作说明见
  设置页 →「增强能力」→「高级授权（adb）」；授权后首页出现
  「恢复无障碍授权」按钮，与 Shizuku 是否安装无关
- **Shizuku 通道**：已装并启动 [Shizuku](https://shizuku.rikka.app/)
  时提供「用 Shizuku 恢复无障碍授权」按钮
- 两条通道都采用 **读取 → 合并 → 写回 → 回读验证**：只追加 NoAd
  自己的条目，**其他应用的无障碍授权原样保留**；写回后重新读取
  确认生效才报成功
- 成功后系统自动重新连接无障碍服务，无需再手动开启
- 两条通道都不可用时按钮不出现，回退手动图文引导

**自动恢复（adb 高级授权用户专享，R14）**：完成 adb 授权后，
连这一下点击也省了——打开 NoAd 时若检测到授权丢失且应用内拦截开关
处于开启状态，会**自动恢复并提示「检测到授权丢失，已自动恢复」**，
全程零点击。安全边界：

- 仅当您主动打开应用时才自检恢复（打开应用 = 想用；您在系统设置里
  手动关闭无障碍时不会打开应用，两者绝不冲突）；
- 仅走 adb 高级授权通道，绝不自动调用 Shizuku；
- 自带防拉锯节流（30 秒间隔 + 每进程 10 次上限），手动按钮不受限；
- 被一键清理**杀死**后应用无法在后台自己醒来（Android 安全设计），
  打开应用的一瞬间即自动恢复——这已是系统允许的极限。



### 排查拦截是否生效

排查顺序是**由内到外**的：先用应用内的诊断，logcat 作为补充。
部分厂商 ROM（实测努比亚 NX789J）会抑制应用日志，
`adb logcat -s NoAdAccessibility` 可能完全没有输出，
此时**应用内的「匹配诊断」是唯一可用的排障通道**。

**第 1 步：看规则页顶部的「匹配诊断」卡片**

打开「跳过规则」页，最上方有一张诊断卡片，直接告诉你引擎的结论：

| 卡片显示 | 含义 | 该做什么 |
|---|---|---|
| 尚未收到任何界面事件 | 无障碍服务没收到事件 | 检查无障碍授权是否真的生效 |
| S1 总开关未开启 | 服务在跑但总开关关了 | 打开 S1 总开关 |
| 应用未纳管 | 该应用没被勾选 | 去「应用管理」页勾选它 |
| 无可用规则 | 已纳管但没有规则覆盖 | 该应用暂未被内置规则覆盖 |
| 界面不匹配 | 规则的 activity 限定不符合当前界面 | 相关规则限定过窄 |
| 未命中任何节点 | 有规则但界面上没有符合的节点 | 该应用跳过按钮可能已改版 |
| 事件预筛未通过 | 事件文本与所有规则都不沾边，未做节点遍历 | 正常降频，仅当疑似漏拦时才关注 |
| 取不到界面节点 / 节点树为空 | 读不到界面内容 | 系统权限限制或界面正在切换 |
| 已点击：… | ✅ 正常工作了 | 无需处理 |

卡片同时显示**当时可用的规则条数**。若显示 `0`，
说明规则没有加载 —— 这排除了"规则写错"，问题在导入环节。

卡片底部还有一行**单次处理耗时**：

```
单次处理耗时：最近 3ms · 峰值 7ms
```

这是给**启动卡顿**排查用的。S1 的事件回调运行在主线程，
如果这行数字长期高于 16ms（一帧的预算），启动应用时就会有可感知的延迟。
正常情况下应当在个位数毫秒；若出现上百毫秒的峰值，
说明点击或节点遍历又回到了主线程路径上，请反馈这行数字。

**第 2 步：看规则列表**

诊断卡片下方应当是按应用分组的规则列表，
例如「通用规则 / 淘宝 / 京东 / 哔哩哔哩」等。

- 「通用规则（适用于所有已纳管应用）」置顶，作用于 SDK 的统一点击按钮
- 标有「应用未纳管」的规则**不会生效**，需先去应用管理页添加该应用
- 若列表整体为空，说明内置规则未导入，S1 不会有任何效果

**第 3 步：看「拦截日志」页**

成功跳过广告时会出现「无障碍」来源的记录。

**第 4 步（可选）：看 logcat**

```bash
adb logcat -s NoAdAccessibility
```

> 注意：部分 ROM 会抑制应用日志，此命令可能无输出。
> 这不是应用故障 —— 此时请以上述诊断卡片为准。
> 日志同样只在**原因发生变化**时输出，不会刷屏。

## 已知限制

- S1 的拦截成功率**高度依赖具体机型与目标应用**，无法保证通用
- 部分应用的广告关闭按钮延迟出现或伪装成其他控件，需要针对性编写规则
- **开屏按钮文案普遍带倒计时**（如「跳过 1」），因此规则必须用前缀/包含
  匹配而非精确匹配；这是设计约束，不是权宜之计
- **无法处理信息流原生广告**（广告内容与正文同域名）
- 部分厂商 ROM 会抑制应用日志，排障请使用规则页的「匹配诊断」卡片
- Android 13+ 侧载安装需手动放行「受限设置」
