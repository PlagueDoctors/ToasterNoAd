- 免 Root 前提下，拦截**弹窗/启动广告**只有 AccessibilityService 一条路。

## 三策略综合方案（本日交付）

用户要求：在 app 内**同时实现**无障碍模拟点击 + DNS/Private DNS 过滤 + 本地 VPN 流量过滤；
本地 VPN 在非 VPN 使用时生效，**有其他 VPN 运行时让位**；定位个人/开源，暂不担法律风险。

- 新建 `reference/THREE_STRATEGY_PLAN.md`——三策略综合技术方案。

### 核心架构结论（重要）

**关键约束**：Android 官方明确规定「同一时刻只能有一个 VPN 连接运行，
新连接建立时旧连接被停用」，被抢占方收到 `onRevoke()`。
→ 因此 **S2(DNS) 与 S3(全流量) 必须设计为互斥模式，不能同时启用**。
  用 `NetworkFilterMode { OFF, DNS_ONLY, FULL_TRAFFIC }` 单开关控制。
→ 但 **S1(无障碍) 与 S2/S3 可同时开启**，因为无障碍服务不占用 VPN 资源。

**让位机制**（用户核心诉求）：
- 用 `NetworkCapabilities.hasTransport(TRANSPORT_VPN)` 检测其他 VPN（排除自身 handle）
- `onRevoke()` 中**绝不自动重连**——否则与其他 VPN 形成无限抢占循环
  （这是 Android 生态「VPN 反复掉线」的典型成因）
- 让位后在 UI 明示，恢复需用户显式触发，不做后台自动恢复

**S2 DNS-only 的精髓**：`VpnService.Builder` 只 `addRoute("10.0.0.1", 32)`
而不 `addRoute("0.0.0.0", 0)`，则仅 DNS 查询进 TUN，网页/下载/视频走原路径，性能影响极小。

**两个必须做对的细节**：
1. 上游 DNS 必须在 `establish()` **之前**读取，否则读到的是自己的虚拟 DNS（死循环）
2. 转发 socket 必须 `protect()`，否则 DNS 请求回流进自己 TUN

**S3 复杂度控制建议**：完整 TCP/UDP 转发是重型工程，建议先用「方案 C：域名级丢包」
（解析 DNS 得域名 → 命中黑名单则丢弃对应 IP 后续连接），避免自实现 TCP 栈。

方案含：单一 VPN 约束与架构决策、VPN 检测与让位仲裁代码、三策略协同图、

## 新增：Shizuku 可选增强方案（本日交付）

用户追加提问：给 Shizuku 额外权限的手机能否做优化。交付
`reference/SHIZUKU_ENHANCEMENT.md`。

### 调研确认的 Shizuku 事实（已核实）

- 原理：用户一次 ADB 启动 Shizuku Server（**UID 2000 shell**，非 root）；
  App 通过 `ShizukuBinderWrapper` 把系统 API 调用转发给 Server 执行。
- **边界**：重启后失效；不能授予 `dangerous` 权限（`pm grant` 无效）；
  不能读其他 App 沙盒；普通 App 进程内仍受 Hidden API 限制；
  shell 权限随 Android 版本 / 厂商 ROM 漂移。
- 官方已明确 **`newProcess` 将被移除，应改用 `UserService`**
  （newProcess 走文本通信，低效且不可靠）。
- `UserService`：在独立进程运行自有代码，UID 2000（ADB）/ 0（root），
  不受非 SDK 接口限制，适合长驻状态与重复 Binder 调用。

### ⭐ 最重要发现：Chain-3 绕过 VPN 互斥

`ShizuWall`（开源，无需 root）已验证：通过 Shizuku 调用 connectivity 服务的
**Chain-3 接口**，可按包名切断联网，**不建 TUN、不占 VPN、可与其他 VPN 共存**。

**这直接解决了主体方案最硬的约束**（S2/S3 因单一 VPN 限制而互斥）。
据此新增「**S4 应用级断网（APP_FIREWALL）**」模式，并让 `VpnArbitrator`
在检测到其他 VPN 时**从「完全让位」升级为「降级到 S4」**。

### 文档覆盖的 6 项优化

| 优化 | 价值 |
|---|---|
| Chain-3 单应用断网 | 🔴🔴 架构级，解决 VPN 互斥与让位后失效 |
| Private DNS 直接改写（`WRITE_SECURE_SETTINGS`） | 🔴🔴 零代码替代 S2，不占 VPN |
| 绕过 Android 13+ 侧载受限设置 | 🔴 侧载必遇问题，体验提升大 |
| 冻结/隐藏/组件停用（`setComponentEnabledSetting`） | 🟡 根治开屏广告（S1 只能等它出现再点） |
| AppOps 权限拒绝 | 🟡 削弱广告 SDK 保活/悬浮窗/设备标识 |
| `forceStopPackage` 强制停止 | 🟡 S1 兜底，但风险最高，建议默认关闭 |

### 设计原则（已写入文档）

1. **Shizuku 是可选增强，不是前提** —— 无 Shizuku 设备核心功能必须完整可用。
2. 每项能力**独立运行时探测 + 独立降级**，不做「有 Shizuku 就有一切」的静态假设。
3. 增强项**默认全部关闭**，由用户显式开启，UI 如实标注状态。
4. `core/shizuku` 只被 Service/Repository 层引用，禁止 `feature/` 直接调用。

## 关键实现决策

1. **手写依赖容器**（`AppContainer`，全 `lazy`）而非引入 Hilt/Koin ——
   单模块、依赖图浅，DI 框架的注解处理收益不划算。
   已记录：ViewModel 超过约 15 个时应重新评估。
2. **领域模型不依赖 Room 注解**，转换集中在 `Mappers.kt`。
3. **枚举以 String 存库**（非序号），避免枚举增删导致存量数据错位。
4. **主键/索引按热路径设计**：`skip_rule.package_name` 建索引（S1 每事件都要按包名取规则）；
   `domain_rule.pattern+is_whitelist` 唯一索引（防重复导入）；`intercept_log.timestamp` 索引。
5. **`DomainRuleEngine` 不可变 + 预编译哈希集合**：匹配为 O(域名层级数)，
   可被 S2 包处理线程与 S3 转发线程无锁并发读取；
   规则变更时由 Repository 重建实例整体替换（Mutex 串行化写路径）。
6. **后缀匹配正确实现**：逐级剥离子域（`a.b.example.com` → `b.example.com` → `example.com`），
   而非 `endsWith` —— 后者会让 `badexample.com` 命中 `example.com`。
7. **应用管理语义**：开关关闭 = **删除**纳管记录，而非置 enabled=false，
   使「受保护应用数」语义清晰。
8. **UI 重构**：首页新增「三策略状态」列表（如实标注未生效原因而非笼统显示"已保护"）；
   网络页把互斥约束表达为**单选分组**（从交互层杜绝冲突配置），
   并明确标注每种模式是否占用 VPN；新增底部导航「网络过滤」等入口。

**选取标准**（写入 JSON `meta.criteria`，作为后续扩充硬约束）：

## 阶段 B：S1 无障碍实现（已完成）

### 新增文件（12 个主源码 + 2 个测试）

`core/engine/ui/`：
- `NodeSnapshot.kt` —— 节点只读快照。**核心决策**：`AccessibilityNodeInfo`
  无法在 JVM 单测中构造、必须成对 recycle、只在回调期有效。不抽象则
  "该不该点这个节点"完全无法测试，而 S1 是四种策略里唯一代替用户操作界面的。
- `NodeRecycler.kt` —— `recycle()` 自 **API 33 起弃用**（框架接管生命周期），
  但 `minSdk=30` 意味着 API 30–32 上不回收是**真实原生内存泄漏**。
  集中做版本分支，而非在调用点 `@Suppress` 后删掉回收调用。
- `UiTreeScanner.kt` —— BFS（非 DFS，因匹配需"浅层优先"），上限 2000 节点防 ANR，
  跨应用节点不展开子树，队列剩余节点必须 drain 回收。
- `UiMatcher.kt` —— 纯逻辑匹配。VIEW_ID > TEXT > DESCRIPTION > COORDINATE。
  viewId 支持短名匹配（`substringAfterLast('/')`），换包名后规则仍可用。
  COORDINATE 不"找最近节点"而是合成虚拟节点 —— 强行就近匹配会把点击目标改到别处。
- `AntiMisclickGate.kt` —— 三重闸门：规则冷却 3s + 节点冷却 5s + 全局节流 400ms。
  成本不对称：漏点=广告没关掉，误点=可能触发付费。有 prune 防记账泄漏。
- `ClickExecutor.kt` —— 三级降级：节点自身 → 向上找可点击祖先（≤5 层）→ 坐标手势。
  "向上找祖先"是关键：广告跳过 TextView 自身 `clickable=false`，响应的是父容器。

`core/repository/S1RuleCache.kt` —— 按包名分组的不可变快照（AtomicReference），
  由 Flow 重建。事件回调在主线程，禁止查库。

`core/service/`：
- `NoAdAccessibilityService.kt` —— 不做保活（无障碍是系统级服务，额外保活是画蛇添足）。
  动态设置 serviceInfo（部分 ROM 忽略 XML 的 flags）。
- `AccessibilityStateHolder.kt` —— StateFlow 发布真实状态。双轨：服务回调为权威 +

- `event/EventProcessor.kt` —— 四道闸门：包名 → 事件类型 → Activity → 防误点。
