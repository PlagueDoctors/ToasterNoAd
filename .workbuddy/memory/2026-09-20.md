## 🎯 全挂根因确认 + 修复（00:45，1.2.4-s2localfix）

hex dump 实锤：TUN 里全是 IPv6 ICMPv6 NDP（60 00 ... FE80...），**零个
IPv4 DNS 查询**。追问「查询去哪了」：`ping 10.0.0.1` 得到 ttl=64、
0.097ms 的**内核本地应答**（logcat 无包）——**10.0.0.1 被 addAddress 配
成 TUN 自身地址后，发往它的查询被 `ip rule` 第 0 条 local 表劫持交给本
机协议栈**（UDP:53 无人监听=丢弃），永远到不了 TUN 用户态。plan §4.1
「addAddress 与 addDnsServer 同用 10.0.0.1」是方案级错误，桌面测试的
构造包根本不含这个语义（只测了解析与校验和），所以 380 例全绿也测不出。

修复（1.2.4-s2localfix，versionCode 7）：业界标准拓扑——
DNS_ONLY：address=10.0.0.1/32，**dnsServer=10.0.0.2，route=10.0.0.2/32**；
FULL_TRAFFIC：address=10.0.0.2/32，dns=10.0.0.3，route=0.0.0.0/0。
响应包目标 10.0.0.1:port 为本机地址由内核 UDP 栈按端口交付，链路闭合。
VpnTunConfigTest 新增防回归断言：**任何模式 dnsServer != address**。
plan §4.1 方案代码已标注修订。

验证：381 tests 全绿（+1 防回归）+ 0 warning。待用户自建部署复测。

## S1 开屏拦截性能优化（1.3-s1perf，19:15）

用户报 B 站「非广告启动画面 → 广告页」场景拦截慢（>2 秒）。
只读发现定位三个叠加根因（均有代码证据）：① 预筛遇 VIEW_ID 规则整体
放行（安全设计）→ B 站含 VIEW_ID 规则 → **每个内容变化事件都全树扫描**；
② UiTreeScanner 每节点 12 字段 × 跨进程 IPC → 数百节点数百毫秒；
③ 扫描全在**主线程**串行 → 启动期数十事件排队 → 广告出现后等队列清空。

方案（两段式流水线）：主线程只跑零 IPC 闸门（内存查表/事件类型/纯字符串
预筛）→ 投递「最新覆盖」槽位 → return Queued；后台单消费者 drain
（取最新 → 窗口重置 → Activity 闸门 → 扫描 → 匹配 → 防误点 → 点击独立
协程 → 诊断）。**合并等价性**：扫描对象是当前界面快照而非事件对象，
连续 N 事件只处理最新一个不丢信息（等价变换非降级）。

新增/改动：LatestRequestQueue（纯逻辑，4 测试锁定合并）；EventProcessor
重构（submit 纯数据入口 + process 薄适配；clock/log 注入；Queued 中间态、
诊断不双计数；窗口重置 OR 原子标记；gate 单消费者线程契约）；
SkipDiagnostics 加 Queued 分支；Service 改注入 clickAction。

坑 3 个：① 重写时丢了 packageNameOf/ruleCountOf 扩展函数与 AccessibilityEvent
import（各一次编译修复）；② **Android SystemClock/Log 在 JVM 单测抛
"not mocked"，位于消费者首行 → 被 runCatching 吞 → 症状是「后台从未扫描」**
（已用时钟/日志注入根除）；③ 初版测试断言「submit 返回时未扫描」过强
（IO 可能抢先完成）→ 改为断言线程身份。

🔴 顺带修复环境问题：`gradle/gradle-daemon-jvm.properties` 要求 daemon
JDK 25，本机无且 GitHub 下载不可达 → 命令行构建全线失败。解法：在
**用户级** `~/.gradle/gradle.properties` 登记
`org.gradle.java.installations.paths=D:\Android Studio\jbr`（AS 自带 JBR
就是 JDK 25）+ 关闭 auto-download（不改项目文件；AS 能构建正因为用 JBR）。
